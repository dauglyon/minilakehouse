# minilakehouse — implementation handoff, 2026-10-20

Current state of the running prototype, for whoever picks it up next. The other docs serve
different purposes: `WHITEPAPER.md` is the target design, `DESIGN.md` describes the code and
rationale, and the root `HANDOFF.md` is the BERDL/Gravitino review that set this round of
work in motion. This file records what is actually built and running as of this date, what
has been checked, and what is open.

Work lives on branch `identity-passthrough-grants-out-of-opa` (head `e105c72` when this was
written). Nothing is merged to `main`.

## Shape of the system

One policy engine (OPA) decides; every other service either asks it or obeys a credential it
gated. OPA is on the decision path, never the byte path.

| Component | Role now |
|---|---|
| Keycloak | The only token issuer. Holds users (`alice`/`bob`/`carol`) and the `trino` client. Proves identity; holds no group membership. |
| governance | PAP + dataset and table registries (Postgres). Holds group membership and the only copy of every grant. Serves them to OPA (`/internal/*`), keeps the registry fresh against storage, accepts governed ingest (`POST /datasets`), table registration (`POST /tables`), grant changes (`PATCH /permissions/<dataset|table>/<id>`) group changes (`POST /groups`, `PATCH /groups/<name>`) and root ownership changes (`PATCH /roots/<dataset|namespace>/<id>`), records the table lifecycle the gate reports, keeps the access log and each login's session pointer (`POST /internal/accesses`, `PROVENANCE.md`), builds and serves each person's tables in the `governance` namespace (`POST /index/load`, `/governance-index/*`), and creates each person's Polaris principal on first use (`POST /principals/me`). Holds only a least-privilege RGW reader. |
| OPA | The PDP, reachable only by its callers. Rules only: `policy.rego` (Polaris's checks), `tables.rego` (who may view/create a table or namespace — shared by Polaris's checks and the gate), `blob.rego` (files), `groups.rego` (group administration), `governance.rego` (the one fetch that gets a person's groups and the grants each rule needs). |
| gate | The only way to Polaris. Verifies the caller's token; trims listings to what they may view, with its own paging; maps a refusal for a name they may not view to not-found; retries a credential-refused table load without the credential so a see-only person can DESCRIBE; decides table and namespace creation (Polaris authorizes those against the parent only); reports creates and drops to governance; has governance create a person's Polaris principal before their first request; refuses register/rename and paths Polaris would rewrite; has governance log each table credential it passes on and each table write it forwards, refusing the request when that fails; answers for the `governance` namespace's tables (`datasets`, `sessions`, `lineage`) itself. |
| Polaris | Iceberg REST catalog. Validates Keycloak tokens (audience `polaris`), delegates every operation to OPA, vends per-table STS. Reachable only through the gate. |
| broker | Blob vending (Flow C): verifies the client's own token, asks OPA about the named dataset, assumes a role scoped to the folder in OPA's decision: `blob-vendor` to read, `blob-writer` to write (put, delete, no get); has governance log each credential before returning it. |
| login-proxy | In front of Trino so a client session outlives the 5-minute token. Speaks Trino's external-authentication protocol, holds the person's refresh token, forwards a fresh token on every request as the bearer and the `token` extra credential. |
| Trino | Query engine. JWT auth over HTTPS; forwards the person's token to Polaris (through the gate) as the `token` extra credential; reads files with the credential Polaris vends. |
| Ceph RGW | S3 + STS + bucket notifications. Enforces every vended credential. Data on the `ceph_data` volume (`ceph/start.sh`, BlueStore on a file). |
| Postgres | Polaris metastore and the durable `governance` database (named volume). |

Three Docker networks: `default`; `policy` (internal — OPA and its callers only); `catalog`
(internal — Polaris, its backends, the gate, and Polaris's setup jobs). OPA and Polaris
publish no host port; Polaris is reachable only through the gate.

## Grant model as implemented

- **Files/blobs.** A dataset entry carries a prefix and four group sets: `visibility` (see),
  `access` (read), `share` and `write`. `read` implies `see`, as it does for tables. `register_grants` maps a group to the prefix roots it may register
  under; the `stewards` group is the capability to register at all.
- **Tables.** A `table_entries` row carries the id (`<catalog>.<namespace...>.<table>`) and
  five group sets — `see`, `read`, `share`, `write`, `delete` — plus status and location. `write`
  implies `read`; `delete` is required to drop and is implied by nothing. `namespace_owners`
  maps a group to a namespace it owns (and everything under it).
- **Changing grants.** `PATCH /permissions/<dataset|table>/<id>` with
  `{"changes": [{"group", "add": [grant], "remove": [grant]}]}`, Unity Catalog's shape. OPA's
  `allow_change` decides while governance holds the entry's row lock (WHITEPAPER 4.4): `see`
  and `read` change for a `share` holder; `share`, `write`, `delete` for a group owning the
  prefix root (`register_grants`) or namespace (`namespace_owners`). `share` has no other
  effect until derived datasets exist.
- **Groups.** `group_members` maps a group to a person. Membership is read at decision time,
  so a change applies at the person's next request. Tokens carry no groups.
- **Group owners.** `group_owners` maps a group to the groups that own it. Anyone in an owner
  group changes its members and owners (`PATCH /groups/<name>`); a change leaving no owner is
  refused. Only `group-admins` create groups (`POST /groups`), and a name any grant or
  ownership already uses is refused. Seed: `jgi-writers` and `projw-team` own themselves;
  `group-admins` (carol) own `stewards`, `no-access` and itself.
- **Root ownership.** A group owning a prefix root (`register_grants`) or namespace
  (`namespace_owners`) owns everything under it. `PATCH /roots/<dataset|namespace>/<id>`
  changes one root's owners: `group-admins` for a top-level root, and anyone in a group owning
  it or one above it, so an owner delegates part of its tree and can take it back.

Seed data for all of the above is `governance/registry.json`, loaded once into Postgres on
first boot.

## Identity path

The person authenticates to Trino with their own Keycloak token (audience `polaris`) and
attaches the same token as the `token` extra credential. Trino's Iceberg client sends it to
Polaris (through the gate) as the bearer, unexchanged. Polaris names the principal from the
token's `principal_name`; OPA fetches that principal's groups from governance. The broker and
governance verify the person's own token directly. Each service accepts only its own token
audience (`polaris`, `broker`, `governance`, requested as the scope `aud-<service>`;
`keycloak/setup.py`); governance's index-load and principal endpoints, which the gate calls
for the catalog, take `polaris`. A client that logs in through the
login-proxy holds an opaque session id instead, and the proxy swaps in a fresh token per
request.

## Checked on the running stack

Run during the work that produced this handoff, not a standing test suite:

- alice reads `db.t1`; bob, with no grant, gets "schema does not exist" (the same answer as a
  name that does not exist); naming another user is refused as impersonation.
- A see-only person can DESCRIBE a table through the gate; their SELECT fails at storage and
  their INSERT fails with Trino's vended-credential error (not a clean access-denied — see
  open items).
- Broker vending resolves groups from governance; a governed registration
  is allowed for a steward whose group owns the prefix and refused otherwise.
- Gate: listings are trimmed and paged; an unviewable name reads as not-found; creating a
  table requires it to be registered (pending) with the caller in its `write`; dropping needs
  `delete` and purges the files; register/rename and path-rewrite tricks are refused.
- Polaris logs no user tokens; a seeded-but-unknown user (carol) is created on first use; the
  `provisioner` principal may only create principals.
- login-proxy: log in once, reuse the session across queries, bob denied, impersonation
  refused; token refresh exercised by forcing it on every request.
- login-proxy with the real Trino 484 CLI: an interactive `--external-authentication` session
  (`PRINT` redirect handler), its browser leg driven by headless Chromium through Keycloak's
  login form. alice read `db.t1`; with the `trino` client's access-token lifetime set to 40 s,
  a second query in the same session 45 s later succeeded after the proxy refreshed the
  expired token. The lifetime was then restored to the realm's 5 minutes.
- Grant changes: alice, a root owner, gave `jgi-writers` `share` on `projx/private`, then as a
  `share` holder granted and revoked its `read`, and the broker's vend followed (200, then
  403). On `db.t1`, `see` for `projw-team` made `t1` appear in carol's `SHOW TABLES`, and
  revoking it returned "schema does not exist". Refused with 403: changing `read` without
  `share`, `share` by a steward of another root, any change by bob, an unknown id. A file
  dataset's `write` is refused with 400.
- Group changes: carol (`group-admins`) created a group owned by `projw-team` and, as a
  `projw-team` member, added bob; alice adding bob to `jgi-writers` turned his vend of
  `projx/public` from 403 to 200, and removing him turned it back. Refused: creating as alice
  (403), a name already in use or named by a grant (409), changes by a non-owner or on an
  unknown group (403), removing the last owner (409), a malformed name (400).
- Root ownership: carol's registration under `datasets/projx/sub/` was refused (403) until
  alice, owning `datasets/projx/`, gave `projx/sub` to `projw-team`; then carol passed
  `projx/sub/t2` to `no-access` and alice removed that from above. The same for namespaces
  (`lakehouse.db.team`, then a table registration under it). Refused: bob (403); carol as
  `group-admins` on a non-top-level root she doesn't own (403); alice assigning a top-level
  root (403); a malformed root (400). Test rows were deleted afterwards.
- Polaris off the RGW admin key: Polaris now authenticates as `polaris-catalog`, which can
  assume `polaris-vendor` and nothing else (a direct listing of `warehouse/` and assuming
  `blob-vendor` are both refused). With it, alice read `db.t1`, created, wrote and read a new
  table, and dropping it purged all 10 of its files; bob stayed refused; Polaris logged no
  warnings. The broker's RGW user had a `roles=*` capability that let it read role policies
  through RGW's IAM API; with it removed that read is refused, and the broker still vends
  (alice 200, reading with the credential works; bob 403).
- Dataset index: `SELECT * FROM iceberg.governance.datasets` in Trino and a pyiceberg scan
  through the gate both return alice's three rows (two file datasets, one table, with
  `can_read`) and none for bob. Granting and revoking `read` on `projx/private` changed her
  next query's row, under a new path. Governance's file endpoint refuses an unsigned
  request, a wrong secret, and alice's credential on bob's files; the gate refuses creating a
  real `governance` namespace. Trino reaches both the index (governance) and `t1` (Ceph)
  through one storage address with the bucket in the host name, and a table created,
  written and dropped through it purged all its files.
- Polaris list filtering: 1.8.0 still authorizes a table listing once, on the namespace
  (`LIST_TABLES`), and returns every entry (`IcebergCatalogHandler.listTables`); the 1.6–1.8
  release notes add no per-entry filtering. The gate's trimming is still needed.
- Freshness without a sweep: the notification topic is persistent and each event checks one
  folder with a listing capped at one object; the 30-second full re-listing and its unread
  object-count, bytes and last-modified columns are gone. Deleting `projz`'s objects set it
  gone; with governance stopped, a put under `projz` waited in RGW's queue (`Entries: 1`), and
  after governance started the queue emptied and `projz` was live again.
- Index scaling: governance offers OPA only entries whose viewing grants name one of the
  person's groups. At 50,000 live datasets (5,003 visible to alice) a load went from 2.39 s to
  0.25 s; `seed/check-index-narrowing.py` found the narrowed rows equal to OPA's full decision
  for every person, at that size and on the seed.
- Token audiences: each token carries only the audience it asked for. The broker refuses
  `polaris` and `governance` tokens, governance's API refuses `polaris` and `broker` tokens
  (its `/principals/me` takes `polaris` and refuses `governance`), the gate refuses a `broker`
  token, and Trino refuses a `governance` token naming the allowed audience. Every README demo
  runs as written with per-service tokens; the login-proxy session works.
- Grant lookups by caller identity: governance serves `/internal/*` only on port 8443 to a
  client certificate named `opa` from the internal CA (`governance/pki.py`); the shared
  lookup bearer is gone, and OPA's environment holds no secret. Plain HTTP to the old path is
  404; TLS without a client certificate, or with governance's own server certificate, is
  refused at the handshake. The gate's table create/drop reports use the same listener with
  a certificate named `gate` (a create and a drop of `t6` set it live then gone); the gate's
  certificate is refused on OPA's lookup routes, and the old report path on port 8000 is 404.
- Storage events carry a secret: RGW puts the topic's opaque data in every event, and
  `/events` refuses deliveries without it (a POST with no secret and one with a wrong secret
  both got 401, while RGW's own events for `projz` got 200 and its queue stayed empty).
- File `write`: the ingest demo registers `projz` with a `write` grant, takes a write
  credential from the broker, and uploads with it; no storage admin key is involved. That
  credential cannot get, list, or put outside `datasets/projz/`; bob is refused one; `projz`
  went live from the bucket notification and appears in alice's index.
- The CLI deletes the token URI it last polled once it holds the token
  (`HttpTokenPoller.tokenReceived`). The proxy answers that DELETE with 204 and keeps the
  session; before, it fell through to the forwarding route and issued a fresh login challenge.

## Open

1. **Polaris external-principal mode.** Released Polaris refuses a token whose name has no
   stored principal, so governance creates one per person on first use. When a Polaris release
   includes PR #5119 (`external` credential mode, merged on main 2026-09-24, not in 1.8.0),
   set `polaris.authentication.credential-mode=external`, pin that release, and remove the
   provisioner, the `POST /principals/me` endpoint, and the gate's call to it.
2. **See-only INSERT message.** A see-only INSERT fails with Trino's "Failed to initialize the
   vended credentials" rather than access-denied. The only clean fix found was Trino's
   access-control plugin, which adds a second place that decides access; left unbuilt by
   decision.
3. **Login-proxy production hardening, parked.** Sessions are in memory (a restart logs
   everyone out); no browser confirmation page naming the client; flood controls beyond the
   per-source challenge rate limit depend on deployment topology (a trusted proxy and
   validated `X-Forwarded-For`, IPv6 /64 bucketing, distributed rate limiting). A single
   in-memory instance has an irreducible cap-vs-eviction tradeoff under a distributed flood.
4. **Derived datasets and provenance.** Designed in `PROVENANCE.md`. Built: step 1 (the
   access log, session pointer, and the `sessions` and `lineage` tables) and the first part
   of step 2 (declarations as checked, signed inserts into `governance.derivations`). Next:
   what a declaration changes, the target live once everyone who wrote it has declared and its
   grants following its inputs (`WHITEPAPER.md` 4.3); waits on whether a live output written
   again returns to `pending` (`PROVENANCE.md` section 9). Widenings, the other half of
   `share`, follow.
5. **Production hardening.** Everything but Trino's and the proxy's token ports and
   governance's internal listener is plaintext; dev credentials live in `.env`.
6. **Scale.** The gate's table and namespace listings fetch and filter every entry, so they
   grow with the catalog. Storage events are checked as each delivery arrives rather than
   coalesced per folder, so a bulk upload costs one (one-object) check per object.

## Running it

```bash
docker compose up -d --build --wait      # bring the whole stack up
q alice -f /seed/seed-table.sql           # seed the demo table (q is defined in README.md)
```

Gotchas, learned the hard way:

- When recreating a single service, use `docker compose up -d --no-deps <svc>`. A plain `up`
  can re-run the `polaris-setup` one-shot, which **drops and recreates the catalog** — the
  namespace and tables vanish from Polaris (the RGW files and the governance registry remain).
  After that, or after `docker compose down -v` (which deletes the `ceph_data` volume), run
  `ceph-setup`, `rgw-setup`, `polaris-setup` with `docker compose run --rm --no-deps` as needed
  and reseed the table. If governance
  still lists the table as `live` while Polaris has lost it, set that `table_entries` row back
  to `status='pending'` before reseeding, or the gate refuses the create.
- Ceph's and governance's `*.storage.internal` DNS names are network aliases in `docker-compose.yml`.
  Adding one to a running container needs `docker network disconnect` then `connect --alias`
  for every name it should keep (including its service name); recreating the container also
  applies them, and Ceph's data survives that.
- `README.md` defines the `q` helper (one fresh token per command) and `seed/proxy_login.py`
  (log in once through the proxy and reuse the session).
- `ceph/sts-bootstrap.sh` is bind-mounted into the ceph container as a single file. An
  editor or `sed -i` that replaces the file gives it a new inode, which the running container
  does not see; run the current version with `docker compose exec -T ceph sh < ceph/sts-bootstrap.sh`.
- Recreating the trino container regenerates its self-signed certificate; restart
  `loginproxy` afterwards, since it pins Trino's certificate at startup.
- A spare container on the host may already hold OPA's old host port; this stack's OPA
  publishes no host port, so that does not conflict.
